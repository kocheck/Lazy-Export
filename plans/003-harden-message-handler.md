**Goal:** Make the plugin robust against two real defects:

1. **(F3) Null-guard the UI window message handler.** Today the handler casts
   `event.data.pluginMessage` and switches on `.type` with no null check. The Figma host (and
   browser extensions, the iframe runtime, etc.) post unrelated messages that have **no**
   `.pluginMessage` field, so `msg` is `undefined` and `msg.type` throws a `TypeError`. Add an
   early `return` when there is no plugin message.
2. **(F10) A concrete `customName` contract.** Today the Custom Name input is sent as
   `customName.trim() || undefined` with **no validation**, and it flows straight into the export
   filename suffix in the plugin. Define and enforce a contract: allow only
   `[A-Za-z0-9 _-]`, trim, max length 64, and **reject** invalid input with an inline error
   message (`"Use letters, numbers, spaces, - or _"`) — **no silent rewriting**. Validate on the
   UI side (block applying the preset, show the inline error next to the input) **and**
   defensively in the plugin (reject the apply if the name is invalid). Put a single shared
   validator in `src/shared/` so both sides import the same rule.

**Why this matters:** F3 is a crash on perfectly normal host traffic. F10 prevents surprising
filenames / path-injection-ish characters in the export suffix while giving the user a clear,
honest error instead of a silently-mangled name.

**Findings addressed:** F3 (unguarded `msg.type`), F10 (unvalidated `customName` contract).

### Task 1: Create the shared `customName` validator (test first)

**Files:** create `src/shared/customName.ts` and `src/shared/customName.test.ts`.

The validator is the single source of truth for the contract, imported by both the UI and the
plugin. Contract:
- Trim leading/trailing whitespace first.
- An **empty** (after-trim) name is **valid** — it means "use the default asset name". The
  validator returns `{ valid: true, value: undefined }` for empty input.
- A non-empty name is valid only if, after trimming, it matches `^[A-Za-z0-9 _-]+$` **and** is at
  most 64 characters. Otherwise it is invalid.
- The error message is exactly: `Use letters, numbers, spaces, - or _`
- The validator never rewrites the name beyond trimming. It either accepts the trimmed value or
  rejects it.

```ts
/**
 * Shared validation contract for the optional "Custom Name" the user can apply to
 * exported assets. Imported by BOTH the UI (src/ui/App.tsx) and the plugin
 * (src/plugin/main.ts) so the rule cannot drift between the two contexts.
 *
 * Contract:
 * - The name is trimmed first.
 * - An empty (post-trim) name is VALID and means "use the default asset name".
 * - A non-empty name must match CUSTOM_NAME_PATTERN and be <= CUSTOM_NAME_MAX_LENGTH.
 * - Invalid input is REJECTED (never silently rewritten beyond trimming).
 */

/** Allowed characters: letters, digits, spaces, hyphen, underscore. */
export const CUSTOM_NAME_PATTERN = /^[A-Za-z0-9 _-]+$/;

/** Maximum length for a custom name (after trimming). */
export const CUSTOM_NAME_MAX_LENGTH = 64;

/** User-facing message shown when a custom name violates the contract. */
export const CUSTOM_NAME_ERROR = 'Use letters, numbers, spaces, - or _';

export interface CustomNameResult {
  valid: boolean;
  /** The trimmed, accepted value, or undefined for empty / invalid input. */
  value?: string;
  /** Present only when `valid` is false. */
  error?: string;
}

/**
 * Validate (and trim) a raw custom-name input.
 *
 * @param raw - The raw input string (may include surrounding whitespace).
 * @returns A result describing whether the name is acceptable. For empty input
 *          `{ valid: true, value: undefined }`. For an acceptable non-empty name
 *          `{ valid: true, value: <trimmed> }`. For invalid input
 *          `{ valid: false, error: CUSTOM_NAME_ERROR }`.
 */
export function validateCustomName(raw: string): CustomNameResult {
  const trimmed = raw.trim();

  if (trimmed.length === 0) {
    return { valid: true, value: undefined };
  }

  if (trimmed.length > CUSTOM_NAME_MAX_LENGTH || !CUSTOM_NAME_PATTERN.test(trimmed)) {
    return { valid: false, error: CUSTOM_NAME_ERROR };
  }

  return { valid: true, value: trimmed };
}

/**
 * Convenience boolean check for callers that only need pass/fail.
 *
 * @param raw - The raw input string.
 * @returns `true` if the name is acceptable (including empty), else `false`.
 */
export function isValidCustomName(raw: string): boolean {
  return validateCustomName(raw).valid;
}
```

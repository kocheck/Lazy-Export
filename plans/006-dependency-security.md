> **Planned at:** `082adbb`, 2026-06-14
> **For the executor:** This is a self-contained handoff plan. You have zero prior context.
> Implement task-by-task, in order. Steps use checkbox (`- [ ]`) syntax — check them as you go.

**Goal:** Get `npm audit --audit-level=high` to **exit 0** (or have every residual advisory
enumerated with rationale in the PR description), by bumping the **direct** dev/build packages
to their patched versions and resolving **transitive** advisories via parent upgrades or
documented `package.json` `overrides` — while keeping `tsc`, `vitest`, and `npm run build` green.

**Why:** `npm audit` flags vulnerable dev/build dependencies (vitest critical UI-server
file-read/exec, esbuild high RCE, rollup path-traversal, picomatch ReDoS, happy-dom, flatted,
postcss, ws). **All advisories are DEV/BUILD-time only** — the shipped plugin bundle
(`dist/code.js`, `dist/index.html`) bundles **none** of them, so this is dev-machine/CI hygiene,
not a runtime-plugin threat. The gate is still worth passing.

**Findings addressed:** F6 (vulnerable dev/build deps).

**Effort:** M · **Depends on:** **001** (needs the green typecheck + green test suite + the
already-tracked `package-lock.json` baseline). **Do not start this plan until 001 is DONE**
(`plans/README.md` row 001 = `DONE`).

**In scope (only these files may change):**
- `package.json` (dependency version bumps + an `overrides` block if needed)
- `package-lock.json` (regenerated by `npm install`)
- `dist/code.js` (regenerated by build — commit it **only if** the build-tooling bumps change it)

**Out of scope:** Do **not** edit any `src/**` file. Do **not** edit application logic. Do **not**
add `rollup` as a **direct** dependency (it is transitive via `vite` / `vite-plugin-singlefile`).
Do **not** change `react`/`react-dom` (runtime deps, no advisory). Do **not** edit
`dist/index.html` or `dist/manifest.json` (this plan changes no UI source).

## STOP conditions (plan-specific)

- A "Current state" excerpt no longer matches HEAD in a way **not** explained by 001 (scripts) or
  004 (`happy-dom` removal) → drift; STOP.
- A dependency bump breaks `tsc`/`vitest`/`npm run build` and is **still** broken after **one**
  reasonable retry (a different patched version in the fixed range) → **pin that package to the
  last working patched version, document the residual advisory in the PR**, and continue with the
  rest. If **multiple** bumps each fail twice such that the audit gate cannot be meaningfully
  improved, STOP and report.
- An advisory's only fix is a **SemVer-major** of a direct package that breaks the build/tests
  twice → do not force it; document it as a residual and continue.
- `dist/manifest.json` changes after a build → unexpected (this plan edits no manifest source);
  STOP and investigate.
- You would need to add `rollup` (or another transitive) as a **direct** dependency to satisfy the
  audit → do **not**; use `overrides` instead, or document the residual.
- `npm audit fix --force` is never to be run (breaking changes outside this plan's scope).

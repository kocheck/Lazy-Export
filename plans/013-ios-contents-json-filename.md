# 013 — Fix iOS imageset / Contents.json filename derivation

> **Planned at:** `df82c72`, 2026-06-14

**Goal:** Make the iOS advanced-mode exported filenames and the generated `Contents.json` filenames
**always agree**, by deriving the per-image scale marker from the export setting's `constraint.value`
(the source of truth) in **both** places instead of from the freeform `suffix`.

**Why this matters:** In advanced iOS mode the exported file inside the `.imageset` folder is named
from `setting.suffix || '@1x'` (`src/plugin/core.ts:186`), while the `Contents.json` that indexes
those files names them from `setting.suffix ?? ''` (`src/plugin/core.ts:64`). These only agree when
every PNG suffix is exactly `@1x/@2x/@3x` — true for the **built-in** iOS preset, false for **custom**
presets: `PresetCreator` defaults each new export setting to an **empty** suffix
(`src/ui/components/PresetCreator.tsx:41`). When they disagree, Xcode cannot resolve the imageset:
`Contents.json` points at `asset.png` but the file is exported as `asset@1x.png`. Worse, two
empty-suffix PNGs at scales 2× and 3× **pass** `validateIOSMetadataSettings` (it checks the SCALE
constraint, not the suffix) yet both collapse to `asset@1x.png` on export and to a duplicated
`asset.png` entry in `Contents.json`. The scale is already known from `constraint.value`; both sites
should use it.
